# StrategyLab: общий доступ и веб-сервер на Windows

Пакет для текущей репы с P0-07 и последней сводной P0-05/06. Фронт из этих исправлений не заменяется: сервер собирает именно установленную в репе версию.

## 1. Что сделано

- В development все вошедшие пользователи видят все прогоны по умолчанию, даже при ручном старте uvicorn без run.ps1. Явное `REPORT_ACCESS=private` остаётся способом проверить приватный режим.
- Свои конфиги и процедуры каждый пользователь редактирует отдельно; чужой rerun не разрешён.
- Новый маршрут `/pivot/apps` также включён в разрешённое общее чтение: чужая сводная раскрывается до точного списка заявок.
- SQLite использует WAL и ожидание блокировки до 30 секунд. Тест одновременно запускает два настоящих расчёта с разными пулами и проверяет доступ третьего пользователя во время работы.
- Для веб-доступа FastAPI отдаёт собранный React и API с одного origin. Vite снаружи не запускается.
- Внешний режим использует персональные логины/пароли через HTTPS Basic. Cookie с произвольным именем не даёт доступ во внешнем режиме.
- Датасет может оставаться на внешнем Windows-пути. Сервер получает явно выбранный корневой каталог данных; выход за него запрещён. Шаблон конфига подставляет этот корень, если стандартный RUN найден.
- Исправлено выполнение штатных проверок из внутренних snapshot во внешнем режиме. Принимается только код, полностью совпадающий с установленной стандартной проверкой; произвольный Python не разрешается.
- Ссылки из старых HTML-отчётов при скачивании подставляют текущий HTTPS-адрес. Сохранённые файлы старых запусков не переписываются.

## 2. Применение патча

Останови текущий run.ps1/API через Ctrl+C. Из корня репы в Git Bash:

```bash
git status --short
git apply --ignore-space-change --check MULTIUSER_WEB_SERVER.patch
git apply --ignore-space-change MULTIUSER_WEB_SERVER.patch
py -3.14 -m pytest tests/test_multiuser_web.py -q
```

При ошибке `--check` остановиться и прислать вывод: не заменять файлы целиком и не применять старые архивы. Новые исходники, тесты и этот WEB_SERVER.md добавляются самим патчем; их не требуется копировать вручную.

Существующие `db/app.db`, `runs/` и исходный датасет не удаляются и не мигрируют в другую БД. По умолчанию веб-сервер использует ту же `db/app.db` относительно корня репы и те же `runs/`.

## 3. Установить cloudflared один раз

Нужны Python 3.14, Node.js/npm и официальный `cloudflared`.

Официальная страница: https://developers.cloudflare.com/tunnel/downloads/ — раздел Windows, Executable, 64-bit. Скачай EXE и положи его в репу как **`.tools/cloudflared.exe`**. Каталог `.tools` при необходимости создай. Альтернатива — официально установленный cloudflared в PATH.

Файл `.tools/cloudflared.exe` не входит в ZIP и не коммитится. Скрипт не скачивает и не запускает неизвестные бинарники автоматически.

Cloudflare Quick Tunnel выдаёт временную HTTPS-ссылку без покупки домена и без проброса входящего порта на роутере. Он предназначен для демо/тестирования; адрес меняется при новом запуске, гарантии постоянной доступности нет. Для постоянного домена нужен отдельный named tunnel или обычный хостинг.

## 4. Создать пользователей и указать данные

Из корня в Git Bash:

```bash
powershell -ExecutionPolicy Bypass -File ./serve.ps1 -Setup -DataRoot "D:/Destruction/Nuclear Hack/ХАКАТОН_СИСТЕМА_АНАЛИЗА_ИЗМЕНЕНИЙ/ПАКЕТ/ЗАДАНИЕ/data"
```

Здесь DataRoot — **родитель папки RUN-20260827-0001**, не RESULTS и не BEFORE_MASTER. Если данные перемещены, укажи их реальный родительский каталог.

Скрипт создаст отдельное `.venv-web` на Python 3.14 и установит зависимости; старое `.venv` не меняет.

Далее в консоли:

1. Введи своё существующее имя приложения точно в прежнем написании — например `Nikita`. Это сохранит доступ к редактированию собственных конфигов. `Nikita` и `Никита` — разные владельцы.
2. Введи персональный пароль минимум 24 символа либо нажми Enter: скрипт создаст случайный пароль и покажет один раз для копирования.
3. Добавь отдельного пользователя заказчика, например `customer`, с другим паролем.
4. Пустое имя завершает добавление. Можно добавить любое нужное число участников.

Сохрани выданные пароли. Передай заказчику только его имя/пароль. В `.local/web_server.json` записаны scrypt-хеши и настройки путей, а не открытые пароли. `.local`, `.tools` и `.venv-web` добавлены в .gitignore.

Повторный `-Setup` добавляет аккаунты или меняет пароль конкретного введённого имени; остальные сохраняются. Для удаления аккаунта останови сервер и удали его запись из `users` в локальном JSON. После смены настроек сервер запускается заново.

## 5. Получить ссылку

```bash
powershell -ExecutionPolicy Bypass -File ./serve.ps1
```

Скрипт:

1. Проверит свободный порт 8000 и наличие cloudflared.
2. Выполнит npm ci и соберёт текущий фронт с относительным `/api`, даже если в старом frontend/.env был localhost.
3. Запустит HTTPS-туннель.
4. Поднимет один процесс API на 127.0.0.1:8000 с собранным фронтом, общей историей и персональной авторизацией.
5. Проверит `/healthz` и напечатает **`READY: https://...trycloudflare.com`**.

Копируй адрес после `READY`, а не раньше. Заказчик открывает его как сайт, браузер спрашивает его персональный логин и пароль. Устанавливать Python/Node заказчику не нужно.

Для повторного старта без переустановки уже имеющихся зависимостей:

```bash
powershell -ExecutionPolicy Bypass -File ./serve.ps1 -NoInstall
```

Сборка фронта всё равно выполняется, чтобы сайт показывал актуальные изменения. Другой порт можно выбрать через `-Port 8010`; вручную менять адрес в исходниках не требуется.

## 6. Как проверить перед отправкой заказчику

1. Открой READY-ссылку под своим аккаунтом; убедись, что видишь старую историю и свои настройки.
2. Открой тот же URL в другом браузере/профиле под customer. Внешний Basic-вход кешируется браузером, поэтому для другого аккаунта нужен другой профиль/браузер. Кнопка смены пользователя во внешнем режиме скрыта.
3. Проверь, что customer видит прежние прогоны и открывает сводную, pivot, проверки, заявку и BEFORE/AFTER.
4. В одном профиле начни расчёт, во втором продолжи открывать готовые отчёты. При необходимости создай второй собственный конфиг и запусти второй расчёт.
5. Скачай HTML и проверь ссылку обратно на текущий HTTPS-сайт.
6. Проверь ссылку с телефона через мобильный интернет. Это отделяет настоящий внешний доступ от работы только внутри Wi-Fi.

Внешний пользователь видит общие отчёты, но не получает права редактировать чужие конфиги. Он может создать свой конфиг по серверному шаблону и выполнить штатный расчёт. Путь к данным относится к компьютеру-серверу.

## 7. Важные эксплуатационные границы

- Окно serve.ps1, компьютер и интернет должны работать. Не переводить компьютер в сон во время демо.
- Ctrl+C останавливает API и туннель; временная ссылка перестаёт работать. Следующий запуск даст новый URL, прежние прогоны остаются в БД/каталоге runs.
- Уже скачанный HTML содержит адрес того момента. Если туннель перезапущен, скачай HTML заново с нового адреса: сервер подставит новый origin.
- Произвольные workspace/file Python-процедуры во внешнем режиме отключены. Для них остаётся доверенный локальный run.ps1. Внешний режим поддерживает стандартные расчёты и пять штатных проверок.
- Отдельные процессы uvicorn workers не добавляются: сервер запускается с workers=1, расчёты выполняются в существующих отдельных фоновых потоках и имеют разные run_id. Два одновременных расчёта проверены; это не тест сотен клиентов и не обещание неограниченной мощности одного ПК.
- Фоновые задачи не продолжаются автоматически после аварийной остановки сервера. Перед штатной остановкой дождись окончания расчётов.
- Туннель маршрутизирует запросы через Cloudflare; данные и БД хранятся на этом компьютере. Доступ посетителей защищён персональными паролями приложения.
- Штатный путь serve.ps1 использует существующую `db/app.db`. Если раньше применялся Docker volume или нестандартный DB_DIR, это другое хранилище: нужный путь задаётся в `db_dir` локального `.local/web_server.json`, не переносом пустой БД поверх старой.

## 8. Диагностика

- `Port 8000 is busy` — останови прежний run.ps1/API. Два сервера одновременно не нужны.
- `cloudflared not found` — проверь PATH или имя `.tools/cloudflared.exe`.
- Ошибка cloudflared до выдачи URL — пришли текст лога; наличие старого config.yml у cloudflared может мешать Quick Tunnel. Скрипт чужую настройку не удаляет.
- `401` в новом браузере — нужны персональные данные из Setup; произвольное имя из локального демо не заменяет пароль.
- `403 Same-origin request required` — открывай актуальный READY-адрес. Во внешнем режиме изменения идут с того же HTTPS-origin.
- `Dataset directory missing` — проверь DataRoot, dataset.path и подпапки сторон.
- `Only packaged ... allowed` — выбран пользовательский код либо старый снимок не совпадает с установленной штатной проверкой. Для нового внешнего расчёта используй актуальный стандартный шаблон; старые отчёты доступны для чтения.
- Пустая история — сравни напечатанный путь Database с тем, где хранились прогоны. Другой Python сам по себе не должен менять путь БД.

## 9. Проверки и что ещё не выполнено автоматически

Проверены: реальные параллельные расчёты двух пользователей и чтение третьим; разные пулы дают 4 и 1 заявку; владельцы/снимки/артефакты не смешиваются; shared/private режимы; закрытый внешний static+API; внешний расчёт и rerun; запрет произвольного кода; ограничение корня данных; HTML-ссылки; разбор URL из лога туннеля.

Сводная проверяется на последнем пакете из соседнего чата: 26 Node-тестов и production build. Статусы полного Python-прогона записаны в сообщении к пакету/qa-протоколе.

В этом окружении нет доступа к Windows-компьютеру пользователя, поэтому serve.ps1, реальный cloudflared и публичную ссылку нужно запустить/проверить на нём. Ссылка заказчику ещё не создана и не отправлена. PowerShell-скрипт подготовлен и проверен чтением, но исполнение PowerShell здесь недоступно.
