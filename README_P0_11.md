## Фронтеру

Патч уже подключает новый блок в Decision X-Ray. При выборе заявки отображаются:

- Решение BEFORE → AFTER и причина решения BEFORE → AFTER.
- Один из пяти выводов: решение изменилось; атрибуты изменились при прежнем
  решении; изменений нет; сравнение неполное; решение не определено.
- Наблюдаемый источник INPUT_DATA / LOGIC / BOTH / NONE с оговоркой:
  классификация по путям не доказывает причинно-следственную связь.
- Диагностика качества с SOURCE, PATH и деталями. Причина отсутствующего отказа
  не выдумывается. Для неполных данных не выводится «решение сохранено».
- Изменённые PATH и ARRAY_KEY, тип изменения, исходные значения BEFORE/AFTER.
  `NULL (значение)`, `"" (пустая строка)` и отсутствие атрибута различаются.
- «Показать ещё» для следующих 200 строк; исходные JSON/XML открываются прежней кнопкой.

У фронтера с установленным Node:


зависит от отсутствующих в нём Runs/RunDetail — это отдельная работа фронта.

## API

Новый маршрут, отдельный от data_api.py и checks_api.py:

`GET /api/runs/{rid}/apps/{app_id}/explanation?limit=200&offset=0`

Дополнительно `path` и `array_key` — точные фильтры для фокуса на атрибуте.
Фильтры и ID передаются SQL-параметрами. limit=1..1000, offset>=0.

Основные поля ответа:

| Поле | Назначение |
|---|---|
| decision.before/after | Исходные коды решений или null |
| decision.changed | true/false только при полном сопоставимом сравнении; иначе null |
| reason.before/after | Наблюдаемые причины, без подстановок |
| comparison.complete | Полнота сравнения, отдельно от числа замечаний |
| interpretation | code, headline, detail, source, source_label, disclaimer |
| changes | total всех различий заявки, filtered_total после фильтров, limit/offset, rows |
| changes.rows[].BEFORE/AFTER | `{present: boolean, value: string|null}`; настоящий NULL хранится строкой `NULL` |
| quality | total, items и truncated; возвращаются первые 100 замечаний с явным указанием ограничения |

Пропавшая заявка и пропавший атрибут не приравниваются: у первой неполное
сравнение и предупреждение, даже если в comparison есть односторонние строки.
Классификация причин и качества независима: отсутствие причины может давать
quality-замечание при технически полной паре документов.

401 — нет сессии; 404 — чужой/неизвестный запуск или неизвестная заявка;
409 — запуск не завершён или артефакты недоступны/некорректны;
422 — некорректные границы страницы.
