# Русское имя и сообщения интерфейса

Патч поверх `36d1f08` с уже применённым `LOCAL_36D1F08_FIX.patch`.

## Исправлено

- Русское имя вызывало `UnicodeEncodeError`: оно записывалось непосредственно в HTTP-cookie. Для имён с Unicode используется отдельная ASCII-safe cookie, декодируемая на сервере. Старые ASCII-сессии продолжают работать; вход/выход удаляет несовместимую cookie. Staging-аутентификация не меняется.
- Ошибка неудавшегося запуска сохранялась глобально в App и оставалась на странице другого, успешного запуска. Теперь новая попытка и навигация очищают старое сообщение; ошибка текущей операции сохраняется.
- Вложенный JSON ошибки конфигурации преобразуется в текст о конкретном недоступном датасете. Сообщение о уже выполняющейся проверке показано по-русски. Неизвестные сообщения сервера сохраняются, а не теряются.
- Новые проверки: Unicode-вход/выход/смена пользователя, сохранение владельца, форматирование ошибок.

`Никита` и `Nikita` — разные имена пользователей. Исправление не переносит отчёты между владельцами. Для старых отчётов войди прежним именем.

## Применить

Распакуй ZIP в корень репозитория. Новые файлы `errors.ts` и тестов попадут в свои папки; существующие файлы меняет патч.

```bash
git apply --ignore-space-change --check UNICODE_UI_FIX.patch
git apply --ignore-space-change UNICODE_UI_FIX.patch
py -m pytest tests/test_unicode_login.py -q
cd frontend
npm test
npm run build
cd ..
```

При ошибке `--check` остановиться: вероятно, уже пришли изменения команды. Патч повторно не применять. Исходные проверки и backend/main.py патч не затрагивает; ожидаемое обновление P0-07 не заменяет.

Останови старый сервер через Ctrl+C, затем запусти заново:

```bash
powershell -ExecutionPolicy Bypass -File ./run.ps1
```

Обнови страницу браузера. Проверь русское имя и переход после неудачной попытки запуска к успешному отчёту.

## Что означали сообщения на скринах

- `Dataset path does not exist: data/RUN-20260827-0001` — конкретная попытка использовала старый путь. В конфиге нужен реальный абсолютный путь к родителю RESULTS. Русские буквы в пути сами по себе не запрещены. Если последующий запуск завершился, старое глобальное сообщение не описывает его статус; после исправления оно очищается.
- `A checks job is already queued/running for this run` — уже принят один rerun, второе нажатие отклонено. Это не результат FAIL самих проверок. Пока UI не подключил статус задачи, дождись завершения и нажми «Обновить». Сам `Checks.tsx` здесь не изменён, чтобы не конфликтовать с работой P0-07.
- По показанным длительностям весь расчёт занял около 155 с, нормализация — 129 с (~83%). Это узкое место данного запуска. По скрину нельзя установить причину отличия от прежнего 27-секундного прогона.
- Общий процент — доля завершённых этапов и текущего прогресса, а не доля оставшегося времени. Поэтому он долго держится низким во время тяжёлой нормализации, затем быстро растёт.

Ускорение движка этим патчем не заявляется. Следующий шаг производительности — профиль загрузки/нормализации того же набора, конфига и выбранных процедур на компьютере пользователя. Полный набор Windows здесь недоступен.

## Передать фронту

Подключить poll `/api/runs/{rid}/checks/jobs/{job_id}` после rerun, блокировать повторную отправку до терминального статуса, обновлять таблицу по завершении. Показывать текущий этап и его процент рядом с общим прогрессом; не представлять общий процент как оценку времени. Эти изменения относятся к её текущей работе и не входят в этот патч.
