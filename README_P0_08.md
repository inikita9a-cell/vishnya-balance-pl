# P0-08 — HTML → отчёт / карточка заявки

Распаковать весь ZIP в корень репозитория. Готовые новые файлы добавятся,
`engine/report_html.py` обновится. Изменения существующих файлов фронта и
одного старого теста переданы точечным патчем:

```bash
git apply --ignore-space-change --check P0_08_frontend.patch
git apply --ignore-space-change P0_08_frontend.patch
py -m pytest tests/test_report_deep_links.py -q
node --test frontend/tests/deep-links.test.cjs
```

Если `--check` не прошёл, остановиться и прислать вывод. Патч применять один раз.
Ожидается 13 Python-тестов и 3 Node-теста. Node-тестам нужны уже установленные
зависимости фронта (`cd frontend && npm ci`). Новых зависимостей нет.
`data_api.py`, `duck.py` и остальные чужие изменения не затрагиваются.

## Поведение

- «Открыть онлайн-аналитику» ведёт на `?page=report&run=<rid>`.
- APP_IDS ведут на `?page=registry&run=<rid>&filters=<JSON с APP_ID>`.
  Реестр фильтруется по точному APP_ID и автоматически открывает его карточку.
  Если ID отсутствует в реестре, показывается сообщение, другая заявка не выбирается.
- APP_ID и run_id корректно кодируются, включая кириллицу, пробелы, &, /, #, ?.
- После входа пользователь остаётся на целевом экране, а не попадает в историю запусков.
- HTML остаётся самодостаточным: CSS и данные внутри. Только переходы в приложение
  требуют работающих фронта/API и действующей сессии.

## Адрес фронта

По умолчанию `http://127.0.0.1:5173`. Если реальный адрес другой, в YAML
конфига нового запуска указать:

```yaml
frontend_base_url: http://127.0.0.1:5173
```

Или задать `FRONTEND_BASE_URL` в окружении процесса API перед его запуском.
Приоритет: `frontend_base_url` → `FRONTEND_BASE_URL` → прежние
`app_base_url` / `APP_BASE_URL` → адрес по умолчанию.
Значение должно указывать на UI, а не на порт JSON API. Подпапка UI поддерживается.

## Проверка в браузере

1. Перезапустить API и фронт. Выбрать завершённый запуск, созданный через API/UI.
2. Создать новый запуск или повторить проверки, чтобы пересоздался report.html.
   Уже скачанный старый HTML сам не обновляется.
3. Открыть HTML из приложения, сохранить его локально и открыть локальный файл.
4. Нажать «Открыть онлайн-аналитику»: открылся отчёт того же запуска, не JSON.
5. Вернуться к локальному HTML, нажать APP_ID: открыт реестр и карточка именно этой заявки.
6. Обновить страницу: карточка восстанавливается. При необходимости войти:
   после входа остаётся тот же целевой экран.

Использовать реальный API run_id. Каталоги контрольного CLI-прогона P0-10
`.../public` не регистрируются в SQLite как UI-запуски и для этой проверки не подходят.

Проверены HTML/URL-контракты, старые API-контракты фронта, TypeScript реестра
и синтаксис App.tsx. Полный браузерный проход нужен на вашей собранной версии:
в исходном проектном ZIP отсутствуют Runs.tsx / RunDetail.tsx.
