# Вопросы Никите для развития REST API

Контракт проверен по коду `backend/api/*.py` из архива `vishnya-balance-pl-main.zip` (ноябрь 2026).

**P0 — права на запуски.** `GET /api/runs` сейчас читает записи всех пользователей; `GET /api/runs/{rid}`, `/summary`, `/checks`, `/apps` и прочие требуют лишь существующую cookie, не проверяя владельца. Для публичной версии нужны полноценная аутентификация и авторизация доступа к run_id (в том числе для шаринга ссылок).

**P1 — датасет и конфигурация.** В списке запусков есть `config_id`, а в деталях нет ни `config_id`, ни `dataset_id`, ни снапшота YAML. Желательны `dataset_id`, `dataset_name`, идентификатор версии/снимка и `config_id` в деталях. Иначе экран «ИД датасета» честно показывает «—». Можно пока использовать `dataset.path` текущей конфигурации только как ненадёжную подсказку.

**P1 — API реестра.** `POST /api/runs/{rid}/drilldown` сейчас не имеет пагинации и отдаёт только `APP_ID`, решения, переходы, число отличий и причину. Желательны `offset`, `limit`, `total`, фильтрация по полям `segments` (`DECISION_CHANGED`, `HAS_DIFF`, `CAUSE`, `QUALITY_ISSUE`, `CHANGED_BLOCKS`) и сортировка. Нужны также `QUALITY_ISSUE`, `COMPARISON_COMPLETE` и дата заявки для полноценного Decision X-Ray.

**P1 — отчёт по блокам.** `GET /blocks` ограничен 500 строками. Для клика из блока в заявки нужен серверный фильтр по блоку/префиксу `PATH`, а не только равенство колонок comparison.

**P2 — проверки.** `POST /checks/rerun` отдаёт `{ok:true}` до завершения. Хорошо бы добавить статус фоновой операции/время обновления, чтобы UI мог корректно сообщить об окончании.

**P2 — стабильные фоновые очереди.** `threading.Thread` не даёт возобновления после рестарта и не подходит для нескольких воркеров FastAPI.
